# Furuta USB protocol v1

UART0 through COM, 460800 baud, 8N1. Firmware text from an older ASCII bench
program is incompatible. No motor command is sent on app launch.

## Framing

COBS encode the decoded bytes below, then append a 0x00 delimiter. Maximum
decoded packet is 2048 bytes. Receivers discard malformed/oversized frames
until the next delimiter. Multibyte fields are little-endian; floats are
IEEE-754 binary32. Serialize fields explicitly.

| Offset | Bytes | Field |
| --- | --- | --- |
| 0 | 1 | Version = 1 |
| 1 | 1 | Type: 1 command, 2 ACK/NACK, 3 event, 4 samples, 5 burst chunk |
| 2 | 2 | Flags, currently zero |
| 4 | 8 | Host session nonce |
| 12 | 4 | Packet sequence |
| 16 | 2 | Payload length |
| 18 | N | Payload |
| 18+N | 4 | CRC-32/ISO-HDLC over header and payload |

CRC uses reflected polynomial 0xEDB88320, init 0xFFFFFFFF, reflected byte input,
final XOR 0xFFFFFFFF. ASCII 123456789 -> 0xCBF43926.
golden_vectors.json is generated by firmware/test/native_core.cpp and checked
by MATLAB tests, including exact int64 counts beyond double precision.

## Connection and command reliability

Commands and events use bounded UTF-8 JSON. Command envelope:

    {"id":3,"op":"STATUS"}

IDs are positive uint32 integers, monotonically increasing within a session.
ACKs echo id/op and contain ok, error when rejected, and a status snapshot.
They describe firmware state, not independent measurements of driver voltage.

HELLO returns protocol/firmware/capacities, bootId and a fresh challenge string.
SESSION_OPEN must carry that exact bootId and challenge with a nonzero nonce
in its packet header. Repeating the same HELLO or SESSION_OPEN is idempotent.
Old handshake bytes do not recreate a valid session after a new challenge.
After reconnect/reboot, no previous run resumes.

The MCU caches 16 recent request/response pairs, including burst chunks.
Same ID + same payload returns the previous result without repeating the
operation. Same ID + different payload is rejected. An older unseen command
outside the retry cache is rejected. A new connection has a new nonce.
The host retries unanswered requests after one second, up to three sends.

STOP, DISARM and ABORT are accepted without a current session and immediately
disable output, cancel starts and invalidate the arm lease. They do not clear
a latched fault. They can be repeated. Host Stop also ceases heartbeat renewal,
so a lost Stop frame still lets the MCU lease expire.

HEARTBEAT every 100 ms renews an armed device lease. Default timeout is 300 ms.
The actual MCU clock enforces this; no MATLAB timer generates motor waveforms.
The interactive simulator uses a bounded synthetic clock and is labelled as
such; direct simulator tests separately exercise elapsed-time faults.

## Operations

| Operation | Additional JSON fields / response |
| --- | --- |
| HELLO | Protocol, firmware, capacities, bootId/status and challenge |
| SESSION_OPEN | bootId and challenge as decimal strings |
| STATUS / CAPABILITIES / EXPERIMENT_STATUS | Current status |
| HEARTBEAT | None |
| GET_CONFIG | config in response |
| SET_CONFIG | config object; transactional, disarmed, schema 1 |
| SAVE_CONFIG | Explicit CRC-protected NVS write; no position/arming restoration |
| CALIBRATE | target: arm, down, upright, current |
| ARM / START / STOP / DISARM / ABORT / CLEAR_FAULT | Explicit state transitions |
| START_STREAM / STOP_STREAM | Passive acquisition independent of motor arming |
| UPLOAD_BEGIN | Clear staged experiment and validation |
| SET_SEGMENT | index (zero-based), segment object; maximum HELLO maxSegments (256 in 1.3, 16 before) |
| VALIDATE / UPLOAD_EXPERIMENT | Commit staged finite sequence |
| TABLE_CLEAR / TABLE_CHUNK | offset, values (up to 128), total up to 4096 |
| CAPTURE_BURST | seconds, withRun boolean; maximum combined memory 4 MiB |
| BURST_INFO | Actual count, active/pending, overflow and clock/rate metadata |
| READ_CHUNK | channel: adc/core; offset; count, maximum 16 |

Large arbitrary tables are staged in chunks before SET_SEGMENT. Segment table
can be empty to reference the staged table. The app sends 96 values per upload
chunk to keep even long numeric literals under the frame limit.

Waveform fields are defined in ExperimentBuilder.segment and engine.h:
kind, duration, amplitude, offset, f0, f1, phase (radians), duty fraction,
end (ramp endpoint), bitPeriod, seed, logarithmic, linear, tablePeriod,
frequencies/amplitudes/phases and table. Values are normalized signed duty.
PRBS uses a 9-bit LFSR, right shift, feedback = bit0 XOR bit4 into bit8,
period 511; zero seed becomes 1. Boundary samples belong to the next segment.
No arbitrary code or MATLAB expressions are evaluated.

## Core samples (type 4)

Batch header: bootId uint64, configId uint32, runId uint32, dropped uint32,
record count uint16. Each record is exactly 88 bytes:

| Offset | Field | Type |
| --- | --- | --- |
| 0 | DeviceUs | uint64 |
| 8 | Sequence (500 Hz acquisition index) | uint32 |
| 12 | Count | int64 |
| 20 | PendRaw | uint16 |
| 22 | AdcRaw | uint16 |
| 24 | CurrentMv (same ADC conversion) | float32 |
| 28 | FilteredMv | float32 |
| 32 | Requested | float32 |
| 36 | Applied | float32 |
| 40 | PendAgeUs | uint32 |
| 44 | AdcAgeUs | uint32 |
| 48 | MagStatus | uint8 |
| 49 | AGC | uint8 |
| 50 | Magnitude | uint16 |
| 52 | Validity | uint32 |
| 56 | LimitFlags | uint32 |
| 60 | ApplyUs | uint64 |
| 68 | AdcUs | uint64 |
| 76 | PendUs | uint64 |
| 84 | State | uint8 |
| 85 | Reserved zero | 3 bytes |

Validity bits: 0 encoder valid, 1 pendulum fresh/MD detected, 2 ADC fresh and
unclipped, 3 pendulum field warning. MagStatus retains actual AS5600 bits
MD=0x20, ML=0x10, MH=0x08. Weak field is recorded even when raw angles respond.
LimitFlags: bit 0 amplitude, bit 1 slew, bit 2 reversal blanking.
State enum: 0 BOOT, 1 DISARMED, 2 ARMED_IDLE, 3 RUNNING, 4 STOPPING, 5 FAULT.

Live stream rates are 50/100/250 Hz, selected from the 500 Hz core acquisition.
Sequence therefore advances by 10/5/2 in an intact live stream. Full mechanical
burst records retain every captured 500 Hz sample. Do not call intentional
decimation packet loss. Timestamps and counters expose actual gaps/overruns.
The protocol worker batches records to keep the default serial budget below
the single-record-per-frame overhead.

## Firmware 1.2 additions (wire format unchanged)

Protocol stays 1, record layouts and golden vectors are unchanged; older
clients connect without modification. All additions are extra JSON fields.

- ADC oversampling: each ADC tick averages `adcOversample` back-to-back
  conversions. At boot the firmware times 256 reads (`adcReadUs`) and picks
  the largest power of two (max 64) whose reads fit in 40 % of the ADC
  period: measured 24.3 us/read gives 32x at 500 Hz, 16x at 1 kHz, 8x at
  2 kHz. CurrentMv is the average (interpolated between calibrated codes);
  AdcRaw is the rounded average, or the clipped extreme if any read clipped,
  so clip detection is unchanged. Timestamp = centre of the averaging window.
- The MCU current filter runs on every ADC sample, and the overcurrent trip
  uses FilteredMv (raw CurrentMv when the filter output is not yet finite).
  HELLO reports `currentTripSource: "filtered"`.
- HELLO adds `adcOversample`, `adcReadUs`. STATUS adds `filteredMv`,
  `adcOversample`, `adcReadUs`, `adcMaxBusyUs`, `adcMaxGapUs`,
  `adcMaxLockWaitUs`, `adcMaxWakeUs`. `STATUS` accepts optional
  `resetDiagnostics: true` to clear the four maxima.
- CURRENT_ZERO events add `sensitivityMvA` and `adcOversample` next to
  `calMeanMv`, `calSdMv`, `calSamples`.
- Status/config JSON is serialized outside the shared mutex (removes ADC
  overruns at 2 kHz caused by command handling).

Hosts: a freshly opened port discards undecodable frames until the first valid
frame (bytes left from a previous session or a mid-frame start); these are
not link errors. The stream is left running on disconnect.

## Firmware 1.3 changes

- CALIBRATE target arm zeroes the encoder count itself (Count reads 0 at the
  centered position; centerCount reports 0).
- Raised limits: up to 256 segments per experiment (HELLO maxSegments),
  maxDuration up to 3600 s, waveform frequencies below 500 Hz (1 kHz output
  loop), currentTripA setting up to 50 A. maxDuty remains a fraction 0..1.
- Zero-current calibration ignores ADC samples timestamped before the
  calibration started (fixes a 1-sample rejection race in 1.2).

## Firmware 1.4 additions

- Profile fields `deadzonePos` and `deadzoneNeg`: measured breakaway duty per
  direction, as a fraction 0..1, or null when unknown. They are stored in RAM
  (and NVS with SAVE_CONFIG) and returned by GET_CONFIG. The firmware does not
  apply them to commands.
- HELLO reports `firmware: "FurutaWorkbench/1.4"`. Wire format unchanged.

## Firmware 1.5 change

- The ADC_CLIPPED fault (any single conversion inside an oversampled current
  sample at the ADC rail) is removed: motor switching-noise spikes tripped a
  real run at 0.74 A. The `validity` ADC bit still reports clipped samples, and
  Controller::tick still faults with ADC_INVALID_OR_CLIPPED when the averaged
  reading leaves 100–3100 mV or is older than 20 ms.
- HELLO reports `firmware: "FurutaWorkbench/1.5"`. Wire format unchanged.

## Firmware 1.11 change

- Stream packets are sent as soon as one record is queued (before: 4 records or 20 ms). HELLO reports
  `firmware: "FurutaWorkbench/1.11"` and `streamBatching: "immediate"`. Wire format unchanged; a packet may
  carry one or more records as before.

## Burst chunks (type 5)

Firmware 1.1 advertises adcChunkMax=64 and coreChunkMax=16 in HELLO. Older
firmware accepts at most 16 for either channel. Clients must negotiate the
advertised ADC limit or fall back to 16. The record schema is unchanged.

Header: commandId uint32, recordOffset uint32, count uint16, channel uint8.
Channel 1 uses 88-byte core records. Channel 0 uses 22-byte ADC records:
timestamp uint64, raw uint16, millivolts float32, requested duty float32,
applied duty float32. Core batch boot/config/run metadata comes from the
capture/session metadata rather than each 88-byte downloaded record.

Use actual timestamps to check the requested rate and jitter. ADC captures
are task-triggered; no claim of oscilloscope-grade or DMA timing is made.
I2C and ADC sampling are asynchronous; age/apply timestamps are preserved.
